# dailyOS UI Design

## 1. Product Direction

dailyOS는 개인의 실제 생활 데이터를 날짜 중심으로 쌓고, 다시 복원하고, 검색하고, 해석하는 Life Database 서비스다. 현재 구현 기준에서 서비스는 `검색`, `하루`, `기록`, `기타`, `설정`의 모바일 흐름으로 운영한다.

핵심 원칙:

- 기록 입력 4축은 `활동`, `할 일·이벤트`, `하루기록`, `건강`으로 통일한다.
- 모바일과 PC는 같은 데이터를 쓰되, 같은 화면을 억지로 복제하지 않는다.
- 모바일은 빠른 기록과 짧은 흐름 파악을 우선하고, PC는 넓은 조회와 병렬 작업을 우선한다.
- 캘린더는 날짜 기반 공통 허브다.
- 검색과 자연어 검색은 입력 화면이 아니라 조회·해석 계층이다.

## 2. Visual Language

밝고 조용한 개인 OS 톤을 유지한다.

- 배경: `#F5F6FB`
- 표면: `#FFFFFF`
- 강조 표면: `#EEF2FF`
- 기본 텍스트: `#111827`
- 보조 텍스트: `#6B7280`
- 경계선: `#DDE3F0`
- 그림자: 낮고 부드러운 카드 그림자
- 모서리: 외곽 카드 `16px`, 내부 아이템 `12px`, 버튼/입력 `10px`

유형 색상:

- 활동: 중성 + 보조 포인트
- 이벤트: 보라
- 할 일: 초록
- 건강: 핑크/블루
- 문서/설정: 회색 계열

## 3. App Shell

### Current Mobile Shell

- 하단 탭이 기본 탐색이다.
- 현재 탭: `검색`, `하루`, `+`, `기타`, `설정`
- `+`는 기록 추가 진입점이다.
- 나머지 화면은 단일 페이지 안에서 탭, 시트, 패널로 전환한다.

### Future Desktop Shell

- 좌측 고정 사이드바
- 우측 메인 콘텐츠
- 상위 메뉴: `기록`, `DB`, `장소`, `설정`
- `기록` 하위: `활동 기록`, `할 일·이벤트`, `하루기록`, `건강`
- `DB` 하위: `라이프 캘린더`, `갤러리`, `전체 검색`, `사람`, `장소`, `자연어 검색`, `가계부`

## 4. Record UX Rules

### 공통

- 같은 날짜 흐름 안에서 입력과 조회가 이어져야 한다.
- 날짜 이동, 달력 토글, 추가 액션은 상단 한 줄 안에서 해결한다.
- 상세 입력은 별도 레이어, 드로어, 시트 패턴을 우선한다.

### 모바일 기록

- 기본 구조는 `한 줄 날짜 바 + 접히는 달력 + 날짜별 타임라인`
- 달력은 기본적으로 접힌 상태를 허용한다.
- 새 입력은 전체 페이지 이동보다 드로어/시트가 우선이다.
- 개별 카드의 기본 정보 밀도는 높게, 세부 내용은 접어서 본다.

### PC 기록

- 입력 패널과 날짜별 목록을 한 화면에 함께 둔다.
- 같은 데이터라도 모바일보다 더 넓은 비교와 편집에 유리해야 한다.

## 5. Activity Timeline

활동 기록은 “그날 실제로 한 행동”의 타임라인이다.

- 상단: 날짜 이동, 날짜 표시, 달력 토글, 추가 버튼
- 요약: 시간/지출/기록 수 등 핵심 수치
- 본문: 시간순 활동 카드

활동 카드 원칙:

- 접힘 상태에서 핵심 정보만 노출
- 펼치면 장소, 함께한 사람, 메모, 지출 등 세부 정보 노출
- 수정/삭제는 아이콘 중심의 간결한 액션 사용

## 6. Plans Timeline

할 일·이벤트는 활동과 최대한 같은 레이아웃 규칙을 따른다.

- 상단 날짜 바 구조 동일
- 달력 구조 동일
- 카드 접힘/펼침 구조 동일
- 다른 점은 데이터 성격과 배지 표현뿐이다.

표현 원칙:

- 이벤트와 할 일을 한 날짜 흐름 안에서 함께 보여준다.
- 완료 상태, 우선순위, 일정 유형은 배지나 체크 UI로만 구분한다.
- 활동으로 전환 가능한 액션은 상세 영역에 둔다.

## 7. Search UX

검색은 두 가지 진입을 가진다.

- 키워드 검색: 정확한 단어, 날짜, 태그를 빠르게 찾는다.
- 자연어 검색: 문장형 질문을 해석해 후보를 모으고 요약한다.

자연어 검색 화면은 다음 순서로 읽히는 것이 좋다.

1. 질문 입력
2. 기간/대상 힌트 보정
3. 근거 기록 목록
4. 짧은 요약 답변
5. 추가 질문 제안

## 8. Life DB

라이프 DB는 입력보다 조회와 해석에 초점을 둔다.

- 하루: 날짜 기준 통합 보기
- 갤러리: 사진/영상 탐색
- 전체 검색: 전역 키워드 탐색
- 자연어 검색: 질문형 탐색과 요약
- 사람: 관계 축 조회
- 장소: 방문 장소 흐름 조회
- 가계부: 연결 지출/수입 조회

## 9. Responsive Rules

Desktop `>= 1024px`

- 사이드바 고정
- 2열 이상 레이아웃 허용
- 패널 병렬 배치 우선

Tablet `768px - 1023px`

- 데스크톱 구조를 줄여서 사용하되, 과도한 다열은 피한다.
- 패널을 세로 적층 가능하게 유지한다.

Mobile `< 768px`

- 하단 탭 사용
- 카드 1열
- 폼은 드로어/시트 우선
- 긴 설명 카드보다 바로 행동 가능한 UI 우선

## 10. PWA UX Notes

- 앱 이름: `dailyOS`
- 시작 URL: `/`
- 디스플레이: `standalone`
- 설치 후에도 브라우저 없이 쓸 수 있도록 상단/하단 네비 높이를 안정적으로 유지한다.
- 모바일에서는 주소창 유무와 안전영역 차이를 고려해 여백이 깨지지 않도록 설계한다.

## 11. Ongoing Refactor Direction

1. 기록 4축의 모바일 패턴을 더 공통화한다.
2. 검색 화면에 자연어 질문 모드를 붙인다.
3. 공통 카드, 빈 상태, 액션 바, 시트 패턴을 UI 레이어로 더 끌어올린다.
4. 문서는 실제 구현 구조와 항상 같이 업데이트한다.
