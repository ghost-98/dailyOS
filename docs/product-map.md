# dailyOS Product Map

dailyOS는 “기록을 많이 넣는 앱”이 아니라 “내 삶을 다시 조회하고 해석할 수 있게 만드는 개인 DB OS”를 목표로 한다.

## 사용자가 느껴야 하는 가치

- 오늘 무엇을 해야 하고 무엇을 했는지 빠르게 안다.
- 하루가 지나도 그날의 장소, 사람, 소비, 사진, 감정적 맥락을 다시 복원한다.
- 한 달 단위로 생활 패턴과 돈, 건강, 관계의 흐름을 본다.
- 흐릿한 기억을 키워드 검색이나 자연어 검색으로 다시 꺼낸다.
- 장소처럼 별도 관리가 필요한 자산은 독립적으로 보관하되, 라이프 DB와 연결 가능하게 둔다.

## 정보 구조

### 기록 입력

매일 가장 자주 쓰는 입력 공간이다.

- 활동 기록: 실제 행동
- 할 일·이벤트: 계획과 약속
- 하루기록: 짧은 텍스트 맥락
- 건강: 러닝과 몸무게
- 사진: 날짜와 연결된 미디어
- 수입: 날짜 기반 소득 기록

### 라이프 DB

기록의 최종 조회·해석 공간이다.

- 하루: 날짜 기반 전체 복원
- 검색: 정확한 키워드 중심 탐색
- 자연어 검색: 질문형 탐색과 요약
- 갤러리: 사진·영상 중심 탐색
- 사람: 함께한 사람 기준 관계 축
- 장소: 방문 장소 기준 흐름 축
- 가계부: 연결 지출·수입 조회

### 독립 관리

라이프 DB와 연결되지만 별도 관리 가치가 있는 공간이다.

- 사람: 문자열 기반 관계 축과 인물 메모
- 장소: 장소 보관함과 날짜별 장소 흐름
- 설정: 계정, 백업, 데이터 관리

## 검색 포지션

검색은 두 레이어로 나눠서 생각한다.

1. **키워드 검색**
   - 정확한 단어를 빠르게 찾는다.
   - 날짜, 태그, 제목, 메모를 중심으로 탐색한다.
2. **자연어 검색**
   - “지난주 누구랑 어디 갔지?”, “이번 달 운동한 날만 보여줘” 같은 질문을 처리한다.
   - 검색 결과를 단순 나열하는 대신 근거와 요약을 함께 준다.

이 두 레이어는 경쟁 관계가 아니라 연속된 경험이다.

## UI 원칙

- 입력 화면은 “오늘 바로 넣기”가 쉬워야 한다.
- 조회 화면은 “내가 쌓은 데이터가 가치 있어 보이게” 요약과 연결을 먼저 보여준다.
- 같은 데이터는 여러 화면에서 보이더라도 원천은 하나만 둔다.
- 삭제/저장/업로드 같은 액션은 반드시 성공·실패 피드백을 준다.
- 모바일 하단 탭은 현재 구현 기준으로 `검색`, `하루`, `+`, `기타`, `설정`을 둔다.

## 현재 우선순위

1. 하루 화면에서 입력과 조회를 더 잘 이어 붙인다.
2. 검색 화면에 자연어 질문 모드를 붙인다.
3. 사람, 장소, 사진, 가계부의 연결도를 더 높인다.
4. 백업과 복원을 실제 사용자 흐름 안에서 더 안전하게 만든다.
5. 검색 결과에 근거와 맥락이 함께 보이도록 정리한다.
