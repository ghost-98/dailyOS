# dailyOS Product Map

dailyOS는 “기록을 많이 넣는 앱”이 아니라 “내 삶을 다시 조회하고 해석할 수 있게 만드는 개인 DB OS”를 목표로 한다.

## 사용자가 느껴야 하는 가치

- 오늘 무엇을 해야 하고 무엇을 했는지 빠르게 안다.
- 하루가 지나도 그날의 장소, 사람, 소비, 사진, 감정적 맥락을 다시 복원한다.
- 한 달 단위로 생활 패턴과 돈, 건강, 관계의 흐름을 본다.
- 흐릿한 기억을 검색하거나 AI 질문으로 다시 꺼낸다.
- 장소처럼 별도 관리가 필요한 자산은 독립적으로 보관하되, 라이프 DB와 연결 가능하게 둔다.

## 정보 구조

### 기록 입력

매일 가장 자주 쓰는 입력 공간이다.

- 활동 기록: 실제 행동
- 할 일·이벤트: 계획과 약속
- 하루기록: 짧은 텍스트 맥락
- 건강: 러닝과 몸무게

### 라이프 DB

기록의 최종 조회·해석 공간이다.

- 캘린더: 날짜 기반 전체 조망
- 갤러리: 사진·영상 중심 탐색
- 전체 검색: 모든 기록 탐색
- 사람: 함께한 사람 기준 관계 축
- 장소: 방문 장소 기준 흐름 축
- AI 질문: 자연어 기반 기록 해석

### 독립 관리

라이프 DB와 연결되지만 별도 관리 가치가 있는 공간이다.

- 가계부: 일정·할일·이벤트·활동에서 파생된 소비 조회
- 장소: 장소 보관함과 날짜별 장소 흐름
- 설정: 계정, 백업, 데이터 관리

## UI 원칙

- 입력 화면은 “오늘 바로 넣기”가 쉬워야 한다.
- 조회 화면은 “내가 쌓은 데이터가 가치 있어 보이게” 요약과 연결을 먼저 보여준다.
- 같은 데이터는 여러 화면에서 보이더라도 원천은 하나만 둔다.
- 삭제/저장/업로드 같은 액션은 반드시 성공·실패 피드백을 준다.
- 모바일 하단 탭은 사용자의 실제 사용 빈도 기준으로 기록, DB, 장소, 문서, 설정을 둔다.

## 다음 대형 리팩터링 순서

1. `LifeView.tsx`를 조회 화면과 입력 화면 컴포넌트로 추가 분리한다.
2. `CalendarView.tsx`에서 이벤트 폼, 월간 보드, 장소 검색을 하위 컴포넌트로 나눈다.
3. 기록 입력 4축(활동, 할 일·이벤트, 하루기록, 건강)의 모바일/PC UX 패턴을 더 정리한다.
4. 공통 폼 패턴, 빈 상태, 액션 메시지를 UI 컴포넌트화한다.
5. AI 질문용 기록 인덱싱/요약 계층을 별도 모듈로 분리한다.
