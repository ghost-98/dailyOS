# 장소 데이터 체계

dailyOS의 장소 기능은 **기록 스냅샷**, **내 장소**, **NAVER 현재 상태**를 서로 독립적으로 관리한다. 한 계층의 변경이 다른 계층의 과거 데이터를 암묵적으로 수정하지 않는 것이 가장 중요한 원칙이다.

## 1. 세 가지 데이터 계층

### 기록 스냅샷

할 일, 이벤트, 활동을 저장할 때 당시 사용자가 본 장소 정보를 기록에 복사한다.

- 사용자 표시 이름 `name`
- NAVER 원본 이름 `providerName`
- 주소와 좌표
- NAVER 식별자 `providerPlaceId`
- 전화번호, 분류, URL처럼 당시 제공된 부가 정보

장소가 NAVER에서 사라지거나 내 장소에서 해제되어도 이 값은 유지된다. 따라서 과거 타임라인은 기록 당시의 의미를 잃지 않는다.

### 내 장소

`saved_places`는 자주 쓰는 장소를 빠르게 다시 선택하기 위한 사용자별 컬렉션이다. 기록의 소유 테이블이 아니다.

- `name`: 사용자가 바꿀 수 있는 표시 이름
- `provider_name`: 검색 당시 NAVER 원본 이름
- `provider_place_id`, 주소, 좌표: 동일 장소 판별용 정보
- `id`, `place_key`: 기존 데이터와 안전하게 저장·삭제하기 위한 DB 식별 정보

내 장소를 해제하면 `saved_places` 행만 삭제한다. 기존 할 일, 이벤트, 활동의 장소 스냅샷과 확인 캐시는 삭제하거나 변경하지 않는다.

### NAVER 현재 상태

`place_verifications`는 NAVER 검색에서 현재 동일 장소를 확인할 수 있는지 저장하는 사용자별 캐시다.

- `verified`: 동일 장소 후보를 찾음
- `unverified`: API 호출은 성공했지만 동일 장소 후보를 찾지 못함
- `checking`: 클라이언트에서 확인 중인 임시 상태
- `error`: API 또는 네트워크 오류로 확인을 완료하지 못한 임시 상태

`error`는 DB에 `unverified`로 저장하지 않는다. 외부 장애를 장소 폐업이나 삭제로 오인하지 않기 위해서다. 저장된 결과는 7일 동안 사용한 뒤 다시 확인한다. 판정 방식이 바뀌면 검증 키 버전을 올려 이전 오판 캐시를 즉시 무효화한다.

## 2. 장소 식별 규칙

공용 구현은 `src/features/data/places/placeIdentity.ts`에 있다.

식별 키 우선순위는 다음과 같다.

1. NAVER 식별자
2. 유효한 좌표(소수점 다섯 자리)
3. 정규화한 주소
4. NAVER 원본 이름 또는 사용자 표시 이름

동일 장소 비교는 NAVER 식별자가 양쪽에 있으면 이를 우선하고, 없으면 30m 이내 좌표, 마지막으로 완전히 같은 정규화 주소를 사용한다. 사용자 지정 이름은 동일 장소 판별 키로 사용하지 않으므로 이름을 바꿔도 연결이 유지된다.

## 3. NAVER 확인 절차

검증 구현은 `src/features/data/places/verificationApi.ts`에 있다.

1. 주소가 있으면 NAVER Geocoding으로 비교용 좌표와 NAVER가 인식한 건물·주소명을 구한다.
2. `providerName`이 있으면 원본 이름으로, 없으면 기록된 이름을 사용한다. 같은 이름의 전국 검색 누락을 줄이기 위해 `장소명 + 군/구/읍/면`을 먼저 검색하고 장소명만으로 한 번 더 검색한다.
3. 검색 후보에서 동일 `providerPlaceId`를 먼저 찾는다.
4. 식별자가 다르거나 없는 예전 데이터는 지도의 주소 해석 결과와 동일한 좌표를 사용해 150m 이내 후보를 찾는다.
5. 좌표도 없으면 주소가 대응하고 장소명이 호환되는 후보를 찾는다.
6. 지역 검색에 등록되지 않은 주거지·건물이라도 주소가 NAVER Geocoding에서 정확한 위치로 확인되면 `verified`로 본다.
7. 지역 검색과 주소 확인에서 모두 후보가 없으면 `unverified`로 저장한다.

주소 지오코딩 성공만으로 장소가 존재한다고 판단하지 않는다. 건물 주소는 남아 있어도 매장은 사라질 수 있기 때문이다.

## 4. 화면 표시

- 기타 > 지도: 전체 기록 장소의 마커와 카드에 상태 표시
- 하루 > 지도: 해당 날짜 동선 마커와 카드에 상태 표시
- 장소 선택 > 내 장소: 저장한 장소별 상태 배지 표시

`unverified` 마커는 일반 마커와 다른 색으로 표시한다. `error`는 “확인 지연”으로 표시하고 미확인 장소 색을 사용하지 않는다.

## 5. 저장 경로

- 일정: `calendar_events.place_*`
- 할 일: `tasks.place_*`
- 활동: `life_activities.place_*`, `start_place_*`, `end_place_*`
- 내 장소: `saved_places`
- 현재 상태 캐시: `place_verifications`

직접 만든 활동과 이동 기록도 일반 장소, 출발지, 도착지 각각의 원본 이름·식별자·좌표를 저장한다. 일정이나 할 일에서 파생된 활동을 수정할 때도 이 식별 정보가 함께 동기화된다.

## 6. 기존 데이터와 마이그레이션

적용 순서:

1. `supabase/migrations/20260924_add_place_verifications.sql`
2. `supabase/migrations/20260924_refine_place_identity.sql`

새 컬럼은 nullable이므로 기존 기록을 훼손하지 않는다. 과거 기록에 NAVER 식별자나 좌표가 없으면 주소와 이름으로 보수적으로 확인한다. 정보가 부족한 기록을 억지로 새 NAVER 장소에 연결하지 않는다.

## 7. 유지보수 규칙

- 장소 키 생성과 동일성 비교를 화면에서 직접 구현하지 않는다. `placeIdentity.ts`를 사용한다.
- NAVER 확인 문구를 화면마다 새로 만들지 않는다. `usePlaceVerificationStatuses.ts`의 표현 함수를 사용한다.
- 사용자 표시 이름을 NAVER 원본 이름 위에 덮어쓰지 않는다.
- 내 장소 삭제 시 기록 테이블을 연쇄 수정하지 않는다.
- API 오류를 `unverified`로 저장하지 않는다.
- 외부 확인 결과는 영구 사실이 아니므로 `checked_at`을 기준으로 재검증한다.
